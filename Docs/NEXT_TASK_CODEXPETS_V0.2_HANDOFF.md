## 1. 用户期望

下一任务对 Mac 版本 CodexPets 做 review 和修复，目标不只是“把现有图集显示在桌面上”，而是完成以下体验：

1. 用户提供一张角色图片；
2. 系统提取角色最有辨识度的核心特征，包括轮廓、脸、比例、配色、材质、标记和固定道具；
3. 以同一个角色基准生成一组组连贯的贴纸式动作帧；
4. 按 Codex 动作语义确定性合成为完整动态宠物图集；
5. 在 CodexPets 中预览、检查和修复动作质量；
6. 制作完成后安装或导出到 Codex 的宠物目录，使其出现在 Codex“设置 → 宠物”中并可选择使用。

视觉和动态质量要对齐 Codex 内置宠物的完整、连贯、清晰程度。当前花花熊猫虽可导入，但整体效果仍低于用户期望。

## 3. 下一任务的产品结果

将 CodexPets 从“桌面宠物播放器”扩展成“桌面宠物播放器 + Codex 宠物工作室”。第一条完整闭环为：

```text
单张角色图
  → 角色身份基准
  → 9 组标准动作贴纸帧
  → 4 个方向基准 + 16 向连续注视
  → v2 图集确定性合成与 QA
  → CodexPets 预览
  → 安装/更新到 Codex
  → Codex 设置中选择并使用
```

生成能力与运行时必须解耦：图像模型负责角色和动作视觉，确定性工具负责透明背景、裁切、对齐、图集布局、校验和打包，不能让模型直接生成最终大图后盲目接受。

## 4. 资产协议与动作基线

下一版本的新宠物必须是 Codex v2：

- 单格：`192×208`；
- 8 列 × 11 行；
- 最终图集：`1536×2288` PNG 或 WebP；
- `pet.json` 必须写入 `spriteVersionNumber: 2`；
- 标准动作行：`idle`、`running-right`、`running-left`、`waving`、`jumping`、`failed`、`waiting`、`running`、`review`；
- 后两行为顺时针 16 向注视，`000` 表示向上，随后每步 22.5°。

每一动作行必须是一组有连贯节奏的帧，而不是把同一张贴纸机械复制、旋转或随机重绘。所有动作必须由同一个角色身份基准约束。

## 5. 视觉质量红线

- 同一宠物在所有行中保持脸、头身比、轮廓、材质、配色、花纹和固定道具一致；
- 动作贴纸在 `192×208` 实际显示尺寸下仍清晰；
- `idle` 有细微但可见的呼吸或眨眼，不是静态复制；
- 左右奔跑方向正确，步态交替且不反向播放；
- `waiting`、`running`、`review` 语义明显不同；
- 不使用速度线、漂浮符号、地面阴影、白底、残留色键、跨格肢体或裁切身体；
- 16 向注视形成连续动作环，四个基准方向必须一眼可辨；
- 不通过整只宠物旋转、斜切或广域变形伪造注视；
- 任一动作出现身份漂移、尺寸跳变、基线跳动或道具瞬移，都不能打包。
